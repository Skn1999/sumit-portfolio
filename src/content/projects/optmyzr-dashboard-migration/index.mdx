## Overview

Optmyzr is a PPC management SaaS platform serving digital advertising agencies handling high-volume accounts across Google, Microsoft, and Amazon Ads. As part of the Core team, I owned the frontend migration of the platform's two highest-traffic, data-dense applications, the **Account Dashboard** and the **PPC Comparison Tool**.

The goal was simple but mandatory: replace a high-debt, legacy tech stack with a performant architecture where adding support for new ad account types required zero core code changes.

## The Problem

<CaseStudySplit>
  <CaseStudyText>
    The existing dashboard stack was built on Backbone.js with heavy jQuery orchestration and server-side templating. For enterprise accounts pulling massive datasets from external advertising APIs, the interface collapsed under its own weight. 

    * **Severe Performance Deficit:** High-spend account dashboards took between **8 to 10 seconds** to become fully interactive, driving down user retention.
    * **Cascade Re-rendering:** Changing parameters or timeline ranges within a single UI module triggered an un-scoped DOM updates loop across every sibling component on the page.
    * **Rigid Scaling:** Adding a new ad network format (such as Amazon Ads) required manual modifications to the base data layer, view controllers, and styling layouts.

## Engineering & Architecture Decisions

Instead of a generic template rewrite, the solution required separating UI rendering orchestration from data source models through three foundational architectural adjustments.

### 1. Domain State Isolation via Scoped Redux Slices
To halt cascade re-rendering across complex multi-widget interfaces, I implemented a strict boundaries framework:

* **Slice Scoping:** Isolated separate data domains into dedicated Redux slices. Dashboard-wide data notifications were restricted to protect independent widget states.
* **Memoized Selectors:** Components subscribed exclusively to the precise dataset property needed for execution, reducing unnecessary sibling evaluation passes to zero.
* **Reference Stability:** Wrapped complex layout modules in `React.memo` and stabilized functional triggers using `useMemo` and `useCallback` to control referential equality leaks.

### 2. Progressive, Viewport-Driven Data Hydration
Enterprise clients routinely fetch hundreds of metric segments, warnings lists, and visualization nodes simultaneously. Flooding the browser main thread with this data instantly froze the tab view.

I restructured the layer into a progressive asset delivery model:
1. Core frame skeletons render immediately on mount.
2. High-priority alert structures paint initial visible text chunks immediately.
3. Complex line charts and comprehensive metric breakdowns load background payloads asynchronously as their bounding containers enter the viewport.

### 3. Config-Driven Dynamic Rendering
<CaseStudySplit>
  <CaseStudyText>
    To isolate layout generation from core feature code entirely, I designed a configuration engine that instantiates components dynamically based on structural JSON rules.

    ```typescript
    // Abstracted representation of the plug-and-render interface mapping
    import React from 'react';
    import { widgetRegistry } from './registry';

    interface WidgetConfig {
      componentPath: string;
      title: string;
      props: Record<string, any>;
    }

    export const WidgetRenderer: React.FC<{ config: WidgetConfig[] }> = ({ config }) => {
      return (
        <>
          {config.map(({ componentPath, props, title }) => {
            const TargetWidget = widgetRegistry[componentPath];
            if (!TargetWidget) return null;
            
            return <TargetWidget key={title} {...props} />;
          })}
        </>
      );
    };
    ```

    On dashboard initialization, the account type is parsed dynamically from the application routing URL. The orchestrator fetches the mapped configuration map, loops through the metadata structure, and executes instantiation safely without core workflow intervention.

The migration delivered measurable business impact:

* Core application load and time-to-interactive benchmarks dropped reliably to under 1 second, matching modern UX expectations.
* New advertising network integrations migrated from a multi-day core development workflow to a basic configuration-authoring checklist.
* The dynamic rendering structure was formally adopted by engineering leads as the reference codebase architecture blueprint for upcoming platform tools.
* Engineering management invited me to lead a technical framework session teaching advanced React reconciliation mechanics and state isolation architecture to junior developers.
